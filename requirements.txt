# Runtime dependencies - separate from requirements-dev.txt (test/dev
# tooling only: pytest). Stage B1 (server track,
# server/connection_manager.py + server/main.py) is the first part of
# this project that needs a real runtime dependency to actually RUN at
# all - the core game logic under kungfu_chess/ has none, and the
# client layer's OpenCV/`Img` dependency predates this file and was
# never tracked in a requirements file either (out of scope to
# retroactively add here). Kept in its own file, not merged into
# requirements-dev.txt, so `pip install -r requirements.txt`
# (production/server deployment) does not also pull in test tooling
# nobody needs at runtime.
#
# websockets: the standard async Python WebSocket library
# (docs/spec.md §1's "no hand-rolled protocol implementation" applies
# here the same way it already does to pub/sub in
# kungfu_chess/bus/event_bus.py). >=13 is required for the
# websockets.asyncio.server/client API this code uses (ServerConnection,
# websockets.serve as an async-context-manager-or-awaitable Server
# factory) - verified directly against the installed 16.1.1.
websockets>=13

# uvloop: drop-in asyncio event-loop replacement, used only by the real
# server process (server/main.py's own main()) for I/O-bound throughput,
# per Server_Design.md §14. No Windows support - upstream publishes no
# Windows wheels and its own setup.py hard-fails the build there
# (verified directly: `pip install uvloop` on this Windows dev machine
# raises "RuntimeError: uvloop does not support Windows at the
# moment"). The `sys_platform != "win32"` marker below makes pip simply
# skip this line on Windows instead of failing `pip install -r
# requirements.txt`; server/main.py falls back to asyncio's own default
# event loop there (see its own comment at the loop_factory call site).
# Production deployment targets Linux/Kubernetes (Agones) per
# Server_Design.md §14, where this installs and is used normally.
uvloop; sys_platform != "win32"

# asyncpg: async-native PostgreSQL client, matching this project's
# already-async composition root (server/main.py's own main()) - no
# reason to introduce a synchronous Postgres client into an asyncio
# codebase. Used ONLY by Stage I0's own throwaway startup connectivity
# check (server/main.py's `_check_infra_connectivity`) - it does not
# back a real PostgresUserRepository yet, that's Stage I1's own
# deliverable. Unlike uvloop above, this is NOT platform-conditional:
# real Windows wheels exist (verified directly: asyncpg 0.31.0
# installs cleanly via a prebuilt wheel on this Windows dev machine).
asyncpg>=0.29

# redis: the standard redis-py client. Its `redis.asyncio` submodule
# (the one actually used here, not the sync API) is built into this
# same package - no separate async package needed (verified directly
# against the installed 8.1.0). Used ONLY by Stage I0's own throwaway
# startup connectivity check (server/main.py's
# `_check_infra_connectivity`) - it does not back a real
# RedisSessionCoordinator yet, that's Stage I2's own deliverable.
# Unlike uvloop above, this is NOT platform-conditional: it ships as a
# pure-Python wheel with no platform-specific build step.
redis>=5.0
